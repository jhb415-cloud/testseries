## 0. 이 작업이 왜 필요한가 (실행자가 반드시 읽을 것)

애드센스 승인이 2회 거절됐고, 사유는 두 번 다 **"가치가 별로 없는 콘텐츠"**였다.

원인을 GSC 숫자와 저장소 코드로 교차 확인한 결과는 다음과 같다.

| 페이지군 | 사이트맵 URL | GSC 색인 결과 | 페이지당 본문 |
|---|---:|---|---:|
| `sitemap-main.xml` (홈 + 전체목록 + 테스트 59) | 61 | **색인 생성됨 62** ✅ | 평균 2,431자 |
| `sitemap-kkum.xml` (꿈해몽) | 183 | ↘ | 평균 **746자** |
| `sitemap-mbti.xml` (MBTI 사전) | 17 | ↘ **발견됨-색인안됨 197 + 크롤링됨-색인안됨 4 = 201** ❌ | 평균 1,351자 |
| www→apex 리다이렉트 | — | 리디렉션 3 | — |

**183 + 17 = 200 ≈ 201**, **61 ≈ 62**. 오차 1~2 이내로 정확히 맞아떨어진다.

즉 **구글은 테스트 페이지 61개를 100% 색인했고, 꿈해몽 174개 + MBTI 사전 17개를 0% 색인했다.**

특히 "발견됨 - 현재 색인이 생성되지 않음"이 197개라는 건 *크롤링해보고 떨어뜨린 게 아니라, 사이트맵에서 URL만 보고 크롤링 자체를 안 했다*는 뜻이다. 구글이 몇 개 샘플링한 뒤 패턴 전체를 저품질로 확정했다는 신호다.

그 결과 애드센스 심사관이 보는 도메인은 이렇게 된다.

> 전체 266개 페이지 중 **구글 자신이 201개(75%)를 색인 거부한 사이트**

### 이번 작업의 원칙

**콘텐츠를 늘리는 게 아니라 줄인다.** 심사 시점에 "구글이 색인을 통과시킨 62개짜리 사이트"로 보이게 만드는 것이 목표다.

애드센스는 도메인 단위로 승인되므로, **승인만 되면 꿈해몽 페이지에도 광고가 나간다.** 따라서 저품질 200개는 **삭제하지 않고 색인 대상에서만 제외**한다. 사용자는 그대로 접근 가능하고, 승인 후 되돌린다.

### 기술적으로 고칠 건 없다 — 절대 건드리지 말 것

다음은 이미 검증 완료했고 **문제가 아니다.**

- ❌ CSR/렌더링 문제 → **없음.** 모든 페이지가 완전한 정적 HTML. `view-source`로 본문 텍스트 전부 확인됨. 홈 5,306자, 테스트 페이지 평균 2,431자.
- ❌ 리다이렉트 문제 → **없음.** `functions/_middleware.js`의 `www → apex` 301은 표준적이고 올바르다. GSC "리디렉션 포함 3"이 정확히 이것이며 무해하다.
- ❌ 사이트맵 누락 → **없음.** `13-drunk-mbti`, `51-mbti-drinking-party-character`는 `config.json`에 `private: true`로 운영자가 알코올 소재라 의도적으로 내린 것. `mbti-couple-match`는 `DESIGN.md`만 있는 폴더로 페이지가 아니다. 정상이다.
- ❌ 바닐라 JS 정적 페이지 구조 → **문제 아님.** 오히려 잘 만들어져 있다. 프레임워크로 갈아엎지 말 것.

**따라서 이번 작업에서 렌더링 방식, 빌드 파이프라인, 프레임워크를 바꾸는 제안은 전부 기각한다.**

# Task 4 — 로또·도박 인접 신호 제거 (v0.0.3)

**Files:**
- Modify: `index.html`

**목적:** 3차 심사에서 *새로운* 거절 사유가 튀어나오는 걸 막는다.

복권은 Google 게시자 정책상 **제한된 콘텐츠**다. 현재 홈 소개문에 이렇게 써 있다.

> 로또 번호 조합기는 완전 랜덤부터 **실제 최근 당첨 통계 기반**, 운세·꿈 행운숫자 연동, 물리 엔진으로 직접 공을 뽑는 추첨기 게임까지 4가지 방식을 지원합니다.

"당첨 통계 기반"은 당첨 확률 향상을 암시하는 표현으로 읽힐 수 있다. 게다가 `오늘의 운세 → 행운의 숫자 → 로또 조합기` 연동은 **운세 + 도박 결합** 구조로 품질 분류기가 가장 민감하게 보는 조합이다. FAQ는 JSON-LD 구조화 데이터에도 그대로 들어가 있어 구글이 직접 파싱한다.

이번 2회 거절 사유는 "가치 없는 콘텐츠"였으니 이게 주범은 아니다. 하지만 콘텐츠 문제를 해결하고 나면 다음 심사에서 이게 걸릴 수 있다. **한 번에 같이 정리한다.**

> 참고: `index.html` 326행 주석에 `v0.2.8에서 애드센스 심사용으로 숨겼다가...`가 있다. 가족오락관에 이미 같은 방식을 쓴 전례가 있으므로 동일 패턴을 따른다.

- [ ] **Step 4.3** — 검증: JSON-LD가 여전히 유효한 JSON인지

```bash
node -e "
const fs=require('fs');
const h=fs.readFileSync('index.html','utf8');
const m=[...h.matchAll(/<script type=\"application\/ld\+json\">([\s\S]*?)<\/script>/g)];
m.forEach((x,i)=>{ try{ JSON.parse(x[1]); console.log('LD-JSON #'+(i+1)+' OK'); }
catch(e){ console.error('LD-JSON #'+(i+1)+' 파싱 실패:', e.message); process.exit(1); } });
```
