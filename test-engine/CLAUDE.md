# test-engine/CLAUDE.md — 심리테스트 콘텐츠 자동 생성 시스템

이 문서는 `/test-engine/` 폴더 전용 작업 규칙이다. 메인 사이트의 `/CLAUDE.md`(아키텍처 규칙)와는
별개이며, 새 심리테스트 콘텐츠를 추가할 때마다 항상 이 순서를 따른다.

## 트리거
사용자가 다음처럼 요청하면 아래 4-1~4-7 절차를 자동으로 따라 진행한다.
> "새 심리테스트 추가해줘: {주제, 문항, 있다면 결과구간}"

또는 md 파일로 여러 개(예: 20개)를 한 번에 전달한 뒤:
> "다음 3개(또는 원하는 개수) 제작해줘" / "이어서 만들어줘"

## 관련 파일
```
/test-engine/
  CLAUDE.md              # 이 파일 — 작업 규칙 전체
  tests/
    index.json           # 콘텐츠 레지스트리 — 새 테스트 작업 전 항상 먼저 읽을 것
  style-guide.md          # 콘텐츠 톤 스타일 누적 기록 — 새 테스트 작업 전 항상 먼저 읽을 것
```

---

## 4-1. 입력 형식
사용자가 "새 심리테스트 추가해줘" + 주제/문항(+선택적으로 결과구간)을 준다.
- 문항만 주어지고 결과 구간이 없으면, 기존 완성 테스트 톤을 참고해 초안을 작성하고
  **먼저 보여주고 승인받는다.**

## 4-2. 사전 체크
- `tests/index.json` 읽고 id 중복, concept_style 반복 여부 확인.
- scoring_type 판단: 일반 테스트는 sum 또는 type, MBTI 축 테스트는 axis.
  (엔진은 sum/type/quiz/axis 4종 모두 이미 지원하므로 엔진 코드는 재작업하지 않는다.)

## 4-3. 폴더 생성
```
/test-engine/tests/{test_id}/
  index.html   (기존 완성 테스트의 index.html 복사 후 id만 교체)
  config.json
  assets/
```
기존 엔진 파일(engine.js/engine.css/themes/*)은 절대 수정하지 않는다.

## 4-4. 이미지 — 샘플 우선 승인 절차 (★ 핵심, 항상 준수)
1. `style-guide.md`를 참고해 이 테스트에 **가장 재미있게 어울리는 톤**(병맛/진지·감성/
   깔끔·위트/밈·드립 중 선택, 섞어도 됨)을 정하고, 그 톤에 맞는 "컨셉 한 줄"을 작성.
   주제 성격과 안 맞는데 병맛만 억지로 넣지 않는다. 최근 3회 이상 반복된 톤·컨셉은
   피하고 새로운 조합을 제안한다.
2. 커버 1컷 + 결과 이미지 중 1~2컷만 먼저 상세 프롬프트를 만들어 **보여주고 승인받는다.**
   (전체 이미지를 한 번에 생성하지 않는다.)
3. 승인 후 샘플 1~2장만 실제 생성해서 보여준다.
4. "오케이" 받으면 나머지 전체(결과 구간 등)를 같은 톤으로 일괄 생성한다.
5. 수정 요청이 오면 톤/컨셉/프롬프트를 고쳐 다시 1~2장만 시도한다 (전체 재생성 금지).
6. 이미지 생성은 빌드타임 스크립트로 처리하고(런타임 API 호출 금지), API 키는
   Codespaces Secrets로 관리한다.

## 4-5. 배포 연동
- `sections.json`에 적절한 섹션으로 항목 추가 (일반/MBTI존 구분).
- MBTI 계열이면 MBTI존 라우팅에 연결.
- **MBTI 축 4종(E-I/S-N/T-F/J-P)이 전부 완성되면**, 서로의 결과 화면에서
  다른 축 테스트로 이동하는 상호 링크를 추가한다 (전부 완성되기 전엔 생략).
- `sitemap.xml`에 신규 URL 추가.
- 기존 파일(sections.json, sitemap.xml, 메뉴 관련 파일) 수정 전에는
  어떤 파일을 어떻게 바꿀지 먼저 보여주고 승인받는다. 신규 폴더 생성/데이터
  추가 수준은 사전 승인 없이 진행 가능.

## 4-6. 완료 후 QA 체크리스트 (항상 확인 후 보고)
- [ ] 모바일 화면(320~500px)에서 정상 표시되는가
- [ ] 결과 공유카드 저장이 동작하는가
- [ ] 텍스트 볼륨이 충분한가(질문+결과 설명 합쳐 애드센스 콘텐츠 기준에 부족하지 않은지)
- [ ] sections.json / sitemap.xml 반영 확인
- [ ] tests/index.json에 항목 추가/버전 갱신
- [ ] style-guide.md에 이번 컨셉 기록 추가
- 버전은 0.0.1 올리고, 변경/생성 파일 목록 + 사용한 이미지 컨셉을 최종 보고한다.

## 4-7. 여러 개를 몰아서 만들 때 (예: 20개 목록을 md로 한번에 전달한 경우)
- 사용자가 "다음 n개 제작해줘"라고 요청하면, 이전에 완료된 항목을 `tests/index.json`에서
  확인하여 **그 다음 순번부터 n개**를 진행한다 (전체를 한 번에 만들지 않는다).
- 이미지 샘플 승인 절차(4-4)는 배치 내 테스트마다 각각 지킨다 (n개를 뭉쳐서 한 번에
  승인받지 않는다).
- 각 배치 작업을 시작하기 전, 전체 목록 대비 **"현재 몇 개 중 몇 개 완료됐는지"**를
  먼저 요약해서 보여준다. 예) "전체 20개 중 5개 완료. 6~8번(총 3개) 진행할게요."
- 배치가 끝나면 같은 형식으로 갱신된 진행 현황을 다시 보고한다.
  예) "8/20 완료. 다음은 9번부터입니다."
- 사용자가 몇 개를 만들지 정확히 지정하지 않고 "이어서 만들어줘"라고만 해도,
  마지막으로 완료된 지점부터 이어가며 진행 현황을 매번 보고한다.
